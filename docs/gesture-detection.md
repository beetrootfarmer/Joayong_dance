# 제스처(dwell) 판정 방식

곡선택·시작 버튼은 손 모양을 인식하지 않습니다. **버튼 영역이 사람(비-그린 픽셀)에 얼마나 가려졌는지**를
보고, 그 상태가 일정 시간 유지되면 선택으로 확정합니다. 크로마키용 그린스크린이 이미 있으므로
사람/배경 분리 비용이 거의 0이라는 점을 활용한 방식입니다.

구현: [`gesture-ui/lib/gesture.ts`](../gesture-ui/lib/gesture.ts)

## 1. 판정 흐름

1. **전경 비율 계산** (`sampleForegroundRatio`)
   제스처 전용 웹캠 프레임(좌우 반전)에서 버튼 영역 픽셀만 읽어, 각 픽셀을 HSV로 변환합니다.
   그린 범위(`GreenRange`)에 들면 배경, 아니면 전경(사람)으로 세고 `전경 픽셀 수 / 전체 픽셀 수`를 구합니다.
2. **히스테리시스** (`DwellTracker`)
   전경 비율 **55% 이상**이면 게이지가 차기 시작하고, **40% 밑**으로 떨어져야 리셋됩니다.
   임계값이 하나면 경계에서 게이지가 깜빡이기 때문에 두 개로 나눴습니다.
3. **Dwell 1.8초**
   1.8초 유지해야 확정. 지나가는 팔 동작으로 오발동하지 않도록.
4. **재발동 잠금**
   완료 직후 잠기고, 비율이 40% 밑으로 내려가야(손을 완전히 떼야) 다시 활성화됩니다.
   손을 계속 올려두고 있어도 같은 버튼이 반복 완료되지 않습니다.
5. **실패 대비**
   8초간 진행이 없으면 "운영자에게 말씀해주세요" 안내를 띄우고, 운영자가 단축키로 처리합니다.
   제스처와 단축키는 같은 내부 함수(`select_song(id)`, `start()`)를 호출합니다.

## 2. 그린 판정: RGB → HSV로 바꾼 이유

### 이전 (RGB 고정값)

```ts
const isGreenish = g > 90 && g > r * 1.4 && g > b * 1.4;
```

비율 비교(`g > r * 1.4`)는 사실상 색상을 대충 보는 셈이지만, `g > 90`이라는 **밝기 절대값**이 함께 묶여 있어
그림자·주름 진 그린스크린을 사람으로 셌습니다. 참여자가 버튼 근처에 서 있기만 해도 발밑·몸 그림자 때문에
전경 비율이 올라가 **오발동**하는 주원인이 됩니다.

### 이후 (HSV)

HSV는 색을 색상(H)·채도(S)·밝기(V)로 분리합니다. 그림자가 지면 V만 떨어지고 H는 거의 유지됩니다.

```ts
// 배경 = 초록 계열 색상 && 어느 정도 선명함 && 완전 검정은 아님
h >= hMin && h <= hMax && s >= sMin && v >= vMin
```

기본값(`DEFAULT_GREEN_RANGE`): `h 80°~160°`, `s ≥ 0.25`(회색·흰색·피부 제외), `v ≥ 0.15`(아주 어두운 픽셀은 색상이 불안정하므로 전경 처리)

### 샘플 픽셀 비교

| 픽셀 | RGB | HSV (h, s, v) | 이전 | 이후 |
|---|---|---|---|---|
| 밝은 그린스크린 | (40, 180, 60) | 129°, 0.78, 0.71 | 배경 | 배경 |
| 그림자·주름 진 그린 | (20, 75, 30) | 131°, 0.73, 0.29 | **전경 ❌** | 배경 ✅ |
| 발밑 그림자 드리운 그린 | (25, 85, 35) | 130°, 0.71, 0.33 | **전경 ❌** | 배경 ✅ |
| 피부 | (220, 170, 140) | 23°, 0.36, 0.86 | 전경 | 전경 |
| 검은 머리 | (20, 18, 15) | 36°, 0.25, 0.08 | 전경 | 전경 |
| 흰 옷 | (240, 240, 240) | 0°, 0.00, 0.94 | 전경 | 전경 |
| 초록 옷 | (30, 140, 50) | 131°, 0.79, 0.55 | 배경 | 배경 (한계, 아래 참고) |

### 얻는 것

- **그림자·조명 변화에 강함** — 어두운 초록도 색상이 초록이면 배경.
- **현장 조정이 직관적** — "초록 범위를 넓혀라", "채도 기준을 낮춰라"처럼 의미가 분명한 파라미터.
  (이전의 `1.4` 계수는 무엇을 뜻하는지 감이 오지 않음)
- **현장 보정 가능** — 아래 3장의 보정 단축키로 현장 그린스크린 색에 맞춘 범위를 만듭니다.
- **성능 영향 무시 가능** — 버튼 영역만 계산하며, 픽셀당 min/max와 나눗셈 몇 번 추가.

### 바뀌지 않는 것 (한계)

- **초록 옷·소품** — 색상 자체가 같아 HSV로도 배경 판정. 크로마키 합성에서도 같은 문제라 운영 안내로 해결.
- **누구 손인지 구분 불가** — 다인원 시 오판정. 바닥 표시로 대표 1인만 서도록 안내.
- **몸통도 전경으로 셈** — 버튼은 가만히 서 있을 때 몸이 닿지 않는 위치(화면 상단 좌우 등)에 배치해야 함.
- **그린 스필**(손가락·머리카락 가장자리의 초록 번짐)은 픽셀 수가 적어 비율 판정엔 영향 미미.

## 3. 현장 보정 (설치 시 1회)

| 키 | 동작 |
|---|---|
| `Shift+C` | 현재 프레임의 버튼 영역(곡선택 + 시작 전체)으로 그린 범위 보정 |
| `Shift+D` | 보정값 삭제, 기본 범위(`DEFAULT_GREEN_RANGE`)로 복귀 |

**절차**: 행사 조명을 켠 상태에서 버튼 영역에 아무도 없게 비운 뒤 `Shift+C`. 화면 상단에 결과(H/S/V 범위)가 3초간 표시됩니다.

- **계산 방식** (`calibrateGreenRange`): 색상은 평균 ± 3σ(최소 ±20°), 채도·밝기 하한은 관측 하위 2% 값의 80%.
- **실패 처리**: 기본 범위 기준으로 그린이 90% 미만이면(사람·소품이 영역에 있음) 보정하지 않고
  "보정 실패: 버튼 영역을 비우고 다시 시도하세요"를 표시합니다. 잘못된 범위가 저장되는 것을 막기 위함.
- **저장**: 브라우저 `localStorage`(`joayong.greenRange`)에 저장되어 새로고침·재시작 후에도 유지됩니다.
  저장이 안 되는 환경에서는 이번 세션에만 적용됩니다.
- **샘플링 시점**: 버튼 테두리·진행률을 그리기 전의 카메라 프레임에서 샘플링합니다 (오버레이 색이 섞이지 않도록).
- **보정 범위는 기본값보다 좁아집니다** (예: 기본 S≥0.25 → 보정 후 S≥0.59). 오발동은 줄지만 조명이 바뀌면
  그린스크린이 범위를 벗어날 수 있으므로, **조명·카메라 위치를 바꾸면 다시 보정**하세요.

**왜 OBS 전역 단축키가 아닌가**: 운영 단축키(동의·시작·강제정지)는 OBS 스크립트가 받지만, 보정은 카메라 프레임을
가진 브라우저 페이지에서만 할 수 있습니다. OBS → 페이지 방향 채널을 새로 만들면 "페이지 → 파일 → OBS" 한 방향 구조가
깨지므로, 설치 시 1회 작업인 보정은 페이지에서 직접 키를 받습니다. 키오스크 창이면 창에 포커스된 상태에서,
OBS Browser Source면 소스 우클릭 → **상호작용(Interact)** 창을 연 상태에서 입력합니다.
